# 0001. Сеанс — це підтверджене утримання, а статус обчислюється з часу

- Статус: прийнято
- Дата: 2026-10-26
- AC: AC-HOLD-01, AC-HOLD-02, AC-HOLD-05, AC-HOLD-06, AC-HOLD-12, AC-HOLD-18, AC-HOLD-26, AC-HOLD-32, AC-HOLD-33

## Контекст

Глосарій PM: «Підтвердження — момент, коли утримання стає сеансом»; утримання прострочується через 24 години «без
ручних дій» (ознаки успіху). Платформа не дає фонових задач частіше ніж раз на добу (`requirements/product.md`, «Що поза
scope»): статус «Expired» не можна виставити задачею точно в момент прострочення. Статус «Past» залежить від поточного
часу так само (AC-HOLD-32).

## Рішення

- Окремої таблиці сеансів немає: сеанс — рядок `holds` з `confirmed_at is not null`.
- Статус не зберігаємо, а обчислюємо з часу: «Confirmed», якщо `confirmed_at`; інакше «Held», поки `now() <
  expires_at`; інакше «Expired». Слот — «Held» / «Confirmed» за активним утриманням, інакше «Past» з моменту початку
  включно, інакше вільний.
- Одна формула «активного» утримання — у SQL `private.is_active_hold` (тригери й RLS) і в TypeScript `holdStatus` /
  `slotStatus` у `src/lib/scheduling/status.ts` (показ).

## Розглянуті варіанти

- **Окрема таблиця `sessions`** — ні: при підтвердженні дані переносяться з утримання (слот, клієнт, час), і правила «не
  більше одного активного на слот» та «клієнт не перетинається» довелося б перевіряти у двох таблицях.
- **Колонка `status`, яку оновлює задача за розкладом** — ні: задача раз на добу показувала б «Held» до доби після
  прострочення (AC-HOLD-06 вимагає «Expired» з 2026-11-03 14:30), а оновлення частіше — поза межами платформи.
- **`status` як згенерована колонка** — ні: залежить від `now()`, а згенеровані колонки в Postgres лише `immutable`.

## Наслідки

- Прострочення «відбувається саме»: слот знову вільний для показу й для тригера без жодної дії (AC-HOLD-06, 26).
- Формула живе у двох мовах (SQL для запису й RLS, TypeScript для показу) — змінювати обидві в тому самому PR.
- Підтвердження (задача 4.1) — лише `update holds set confirmed_at`, без перенесення даних.
