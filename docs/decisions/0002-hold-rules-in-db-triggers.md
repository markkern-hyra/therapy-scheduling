# 0002. Правила утримання — лише в тригері бази з блокуванням рядків

- Статус: прийнято
- Дата: 2026-10-26
- AC: AC-HOLD-03, AC-HOLD-04, AC-HOLD-07, AC-HOLD-08, AC-HOLD-17, AC-HOLD-25, AC-HOLD-26

## Контекст

Утримання має чотири правила запису: лише admin і scheduler (AC-HOLD-08), не більше одного активного утримання на слот —
і при одночасних спробах (AC-HOLD-03, 04, 17), слот, що вже почався, не утримується (AC-HOLD-07), утримання й сеанси
одного клієнта не перетинаються (AC-HOLD-25, 26). Server Action — публічний POST, а публічний ключ дає прямий запит до
Data API в обхід сторінок, тож правило, яке живе лише в коді застосунку, обходиться. «Активне» залежить від часу (ADR
0001), тому звичайним unique чи exclusion-обмеженням його не виразити.

## Рішення

- Утримання — один `insert into holds (slot_id, client_id)`; правила — у тригері `before insert`
  `private.check_new_hold` (`security definer`, `set search_path = ''`), по черзі: роль (`HOLD_FORBIDDEN`) →
  `select … for update` клієнта, потім слоту (завжди в цьому порядку) → `v_now := clock_timestamp()` → активне утримання
  слоту (`SLOT_TAKEN`) → слот почався (`SLOT_STARTED`) → перетин активних утримань клієнта (`CLIENT_BUSY`) →
  `created_at`, `expires_at = v_now + 24 години`.
- Блокування рядка слоту серіалізує одночасні спроби: друга транзакція чекає першу й після її коміту бачить нове
  утримання — створюється рівно одне (AC-HOLD-04). Блокування клієнта так само серіалізує його утримання в різних
  терапевтів (AC-HOLD-25).
- Код помилки — текст `raise exception '<КОД>'`; `errorCode` у `messages.ts` перекладає його в текст PM дослівно.
  Server Action `holdSlot` лише перевіряє вхід (`getClaims()`) і передає запис; правил не повторює.
- `created_at` і `expires_at` клієнт не задає: GRANT `insert` лише на `slot_id`, `client_id`.

## Розглянуті варіанти

- **Перевірки в Server Action** — ні: «перевірити, потім записати» двома запитами пропускає одночасне утримання
  (AC-HOLD-04), а прямий запит до Data API оминає дію взагалі.
- **RPC-функція `hold_slot`** — ні: ще один шар, а прямий `insert` однаково треба було б заборонити; тригер ловить і дію,
  і прямий запит однаковими кодами.
- **Exclusion-обмеження чи частковий unique-індекс** — ні: «активне» залежить від `now()`, а умови індексів у Postgres
  мають бути незмінними.

## Наслідки

- Правила в одному місці (DRY): сторінка лише не показує «Hold» там, де статус не вільний.
- Нове правило утримання — нова міграція з тригером і тестом бази.
- Одночасність PGlite (одне з'єднання) не відтворює — ручна перевірка двома вікнами в PR задачі.
