# 0009. Форму картки перевіряє TypeScript, база лишається арбітром

- Статус: прийнято; частково замінює 0003
- Дата: 2026-11-02
- AC: AC-CARD-03, AC-CARD-12, AC-CARD-13, AC-HOLD-11, AC-HOLD-15, AC-HOLD-39

## Контекст

ADR 0003 тримав правила форми лише в базі: одне джерело правила, прямий запит отримує ту саму відмову. Але check
зупиняється на першому порушенні, а AC-CARD-12 вимагає показати всі помилки одразу, кожну біля свого поля. Для дитини без
імені база до того ж давала текст для дорослого.

## Рішення

- Чиста `validateCard(values, today)` у `src/lib/scheduling/clients.ts` повертає `{ поле: MessageCode }`. Дія викликає її до
  запису.
- Check і unique у базі лишаються: вони захищають від прямого запиту до Data API й гонки. Дублікат дитини стереже частковий
  унікальний індекс `clients_child_dedup_key`.
- Формат email у TypeScript повторює `clients_email_check` з ADR 0003.

## Розглянуті варіанти

- Лише база й кілька спроб запису — ні: одна відповідь Postgres містить лише одне порушення.
- Функція Postgres, що повертає всі порушення, — ні: для чистої перевірки форми це більше коду без користі, бо check однаково
  лишається.

## Наслідки

- Правило email тепер у двох місцях. Якщо TypeScript пропустить зайве, відмовить база, тож дані не зіпсуються; розходження
  означало б лише інший текст.
- Зміна формату email — і в міграції, і у `validateCard`.
