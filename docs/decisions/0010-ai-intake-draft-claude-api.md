# 0010. Чернетка картки з тексту звернення: Claude API (`@anthropic-ai/sdk`) + zod, ліміт запитів у базі

- Статус: прийнято
- Дата: 2026-11-18
- AC: AC-INTAKE-01, AC-INTAKE-02, AC-INTAKE-03, AC-INTAKE-04, AC-INTAKE-05, AC-INTAKE-06, AC-INTAKE-07, AC-INTAKE-08,
  AC-INTAKE-09

## Контекст

Зріз 4 (вимога PM HryhoriiHaponiukQuitCode/therapy-scheduling-spec#36) — перша AI-функція: текст звернення → чернетка
форми нової картки, яку планувальник перевіряє й сам зберігає. Обмеження:

- Набір курсу (`materials/ai-feature`, ADR-заготовка «AI SDK + OpenRouter») розрахований на власний безкоштовний ключ
  OpenRouter у кожного розробника. Нашій команді видали **один ключ Claude API з бюджетом $50 на всю команду** — для
  AI-функцій продуктів усіх розробників команди. Це платний ключ, тож кожен запит коштує, а бюджет спільний.
- «Помічник має обмежену кількість запитів на добу» («Припущення» PM). У безкоштовного OpenRouter це ліміт акаунта; у
  Claude API такого ліміту немає — його треба задати самим.
- Next.js 16.4 на Vercel Hobby: функція до 300 с; CI без мережі й без секретів; відповідь моделі недетермінована.
- Текст звернення обробляє зовнішній сервіс («Припущення» PM, підказка під полем) — лише синтетичні дані.

## Рішення

- Нові залежності (точні версії, кожна старша за два тижні): `@anthropic-ai/sdk@1.4.0` (офіційний SDK; JSON-схема з zod —
  `@anthropic-ai/sdk/helpers/zod`), `zod@4.6.7`, `server-only@0.0.1`.
- Модель — `claude-sonnet-5-5` (рішення людини: між Opus 5.5 і Haiku 5.5 — дешевша за Opus, надійніша за Haiku на відмові
  й ін'єкції, які поріг PM робить обов'язковими), `output_config.effort: "low"`, `output_config.format` — JSON-схема
  відповіді; серверний `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) — лише на відмову класифікатора
  безпеки. Без інструментів, без стрімінгу, `maxRetries: 1`, таймаут 25 с.
- Модель повідомляє факти (`src/lib/ai/intake-schema.ts`), правила PM застосовує чиста `draftFromModelText`
  (`src/lib/ai/intake-draft.ts`); стани `ok / needs_info / refused / unavailable`. Ключ `ANTHROPIC_API_KEY` читає й
  клієнт SDK створює лише `src/lib/ai/anthropic.ts` з `import "server-only"`; без `NEXT_PUBLIC_`.
- Ліміт — 50 запитів на добу практики на застосунок: функція бази `take_assistant_request()` (задача 1.2
  `impl-client-intake-draft`); вичерпано — AC-INTAKE-08.
- Якість — 10 golden cases PM: офлайн-реплей справжніх записаних відповідей у `npm test` (CI), живий прогін
  `npm run eval` вручну, звіт у `evals/reports/`.

## Розглянуті варіанти

- OpenRouter `:free` з набору курсу — ні: команда отримала ключ Claude API, а безкоштовні моделі змінюються й мають
  спільний денний ліміт акаунта; набір лишився зразком будови (схема, межа ключа, реплей, eval).
- Vercel AI SDK (`ai`) з провайдером Anthropic — ні: зайвий шар над офіційним SDK; помилки (`RateLimitError`,
  `APIConnectionTimeoutError`) і тестовий клієнт (підмінений `fetch`) дає сам SDK.
- `client.messages.parse` — ні: при невалідному JSON він кидає виняток, а для запису й реплею потрібен сирий текст
  відповіді, тож парсимо самі тією самою zod-схемою.
- Opus 5.5 — ні: рішення людини перейти на дешевшу модель. Haiku 5.5 — ні: найдешевша, але слабша на ін'єкції й відмові.
- Ліміт лише бюджетом ключа ($50) — ні: один застосунок міг би витратити бюджет усієї команди.
- Скрипти набору `ai:models`, `ai:quota` — ні: вони про OpenRouter; модель фіксована, ліміт — у нашій базі.

## Наслідки

- Простіше: один постачальник і одна модель; CI не залежить від мережі й ключа; модель міняємо в `INTAKE_MODEL`.
- Складніше: кожен запит платний — ліміт 50/добу й `maxRetries: 1`. UAT і приймання PM на проді ділять ліміт бази;
  живий `npm run eval` іде в API напряму (повз ліміт бази) і ділить лише бюджет ключа — 10 запитів на прогін.
- Записи `tests/fixtures/golden/recorded.json` оновлюємо (`RECORD=1 npm run eval`), коли змінюється промпт
  (`INTAKE_PROMPT_VERSION`), схема чи модель.
